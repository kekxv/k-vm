# k-vm Sandbox Implementation Plan

**Goal:** Add a native sandbox entry point with confined host file mappings, local images, transient disks, and configurable networking.

**Architecture:** `src/sandbox/` validates local image bundles and launch options, then fills existing machine parameters. `src/storage/fs_confined.c` provides a separate descriptor-based 9P backend with host-enforced read-only access and Linux openat2 confinement. Existing VM mode remains compatible.

**Tech Stack:** C, Bazel 7.4.1, Linux openat2 (kernel >= 5.6), existing VirtIO/SLIRP.

**Constraints:** Local files only during sandbox startup; disk writes default to transient snapshots; mappings default read-only with explicit rw; network user/none/tap; do not equate an old emulator with an audited hostile-code isolation boundary.

- [x] Write failing C tests for filesystem traversal/symlink escape, host-enforced readonly, directory mapping and single-file mapping.
- [x] Implement confined backend and pass tests, including mutating 9P operations.
- [x] Write failing sandbox launch tests using generated local RV BIOS and raw image, mapping flags, invalid config and network options.
- [x] Implement `k-vm sandbox --image DIR_OR_CFG --map TAG=HOST[:ro|rw] --network user|none|tap:IFNAME`, local image preflight and default snapshot disks.
- [x] Verify quick cold startup with local minimal BIOS; describe measured scope rather than promise snapshot restore.
- [x] Document image bundle, guest mount commands, mapping policy, local raw image support and network/exit behavior.
- [x] Run default and SDL regression tests, verify tools and independent code review.
