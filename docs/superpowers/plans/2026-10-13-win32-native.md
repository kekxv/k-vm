# Native Win32 implementation plan

Goal: build and run a native Windows x64 k-vm.exe without WSL, preserving RISC-V shell/Pi, current directory mappings, SLIRP networking, and transactional Pi update.
Architecture: choose Windows implementations in Bazel. Secure mapped files use Win32 handles with reparse points refused and checked paths; native console uses VT sequences and Windows input/resize handling; disk updates use handle locks and atomic replacement. Keep Unix implementations unchanged.

- [x] Implement handle-based Win32 9P filesystem and path helpers; compile and add native regression tests for writes/read-only/path/reparse/ADS escapes.
- [x] Implement Win32 console, host event loop and Winsock/SLIRP initialization; cross-compile frontend and networking.
- [x] Implement Win32 disk/workspace/update lifecycle and native path handling, preserving minimal config imports and failure/interruption preservation.
- [x] Select native sources/toolchain settings in Bazel, add Windows build/test CI, remove WSL as required Windows runtime and document native usage.
- [x] Run Linux regression suites, Windows cross-build and runnable native checks where feasible; independently review and record verification limits.

Ruling: initially Windows x64 using MinGW-w64 GCC (supports __int128), not MSVC — avoids rewriting the RISC-V interpreter. Windows 10/11 VT-capable terminals required for interactive Pi. Native runtime may omit legacy remote HTTP filesystems/image downloading; guest networking remains supported through SLIRP. No Git metadata exists in this workspace.
